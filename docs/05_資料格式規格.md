# 05 資料格式規格

> 版本：v1.0（2026-11-01）
> 狀態：**已確認**。之後的變更走版本號。
> 機器可讀定義：`schema/*.schema.json`、`config/source_field_map.json`

---

## 1. 範圍與原則

本文件定義三件事：

1. 目錄權限與路徑（什麼能讀、什麼能寫）
2. 命名規則（哪些地方必須英文，哪些地方可以中文）
3. 資料檔的結構（輸入來自 novel-studio 的書，輸出是 scene graph、角色表、素材清單）

### 1.1 三條硬規則

| # | 規則 | 原因 |
|---|---|---|
| R1 | 所有 key、ID、程式會讀的檔名與資料夾名只用 `[a-z0-9_]` | novel-studio 的問題：中文 key 讓跨語言工具難以處理，檔名編碼在 Windows 上也常出錯 |
| R2 | 顯示用文字可以是任何語言，但必須放在「值」或 `names`／`title` 這類 i18n 物件裡 | 之後加日文、英文不用改結構 |
| R3 | 書目錄唯讀；所有產出寫在 `works/<book_id>/` | 原稿不會被誤改 |

---

## 2. 目錄權限與路徑

| 名稱 | 路徑（Windows） | 權限 | 用途 |
|---|---|---|---|
| 專案目錄 | `E:\text_2_visual_novel` | 讀寫 | 本專案 |
| 書目錄 | `%USERPROFILE%\Documents\小說` | 唯讀 | 小說來源（每本書一個子資料夾） |
| novel-studio | `E:\novel-studio` | 唯讀 | 只在複製模組時讀取 |


`config.yaml` 由 `config.example.yaml` 複製而來，不進 git。路徑只放在 `config.yaml`，程式碼不寫死。

## 3. 命名規則

### 3.1 什麼要英文（key 層）

| 類別 | 規則 | 範例（對） | 範例（錯） |
|---|---|---|---|
| JSON/YAML 欄位名 | `^[a-z][a-z0-9_]*$` | `scene_id`, `time_of_day` | `場景ID`, `時間` |
| book_id | `^[a-z][a-z0-9_]{1,30}$` | `sample_book` | `示範`, `sample-book` |
| char_id | 同上 | `ellie_reed` | `艾莉`, `ellie`（同名多人時要有區分） |
| location_id | 同上 | `scrapyard` | `舊工坊` |
| scene_id | `^ch\d{3}_sc\d{2}$` | `ch001_sc03` | `第1章3場` |
| chapter_id | `^ch\d{3}$` | `ch001` | `第001章` |
| asset_id | 同 char_id | `bg_scrapyard_dawn` | `舊工坊_清晨` |
| enum 值 | 同上 | `dawn`, `tense` | `清晨`, `緊張` |
| 程式會讀的檔名 | 小寫＋底線 | `scene_ch001.json` | `第001章.json` |

### 3.2 什麼可以是中文（值層）

- `names`、`title`、`label`、`text`（台詞本文）等顯示用欄位。
- `aliases`（原文寫法，用來比對，例如 `"老張"`、`"老陳"`）。
- `source` 裡引用的原文路徑與段落說明。
- `docs/` 下的說明文件（中文檔名可以）。

### 3.3 i18n 物件

多語名稱統一寫法：

```json
"names": { "zh-TW": "艾莉・里德", "en": "Ellie Reed" }
```

- key 是 BCP-47 語言標籤（英文字元），value 是該語言的文字。
- 至少要有一個語言；`lang` 欄位（見 5.1）決定台詞本文的語言。
- 目前只做繁中，`en` 與 `ja` 之後再補；不要因此改結構。

### 3.4 ID 穩定性

- ID 一旦寫入 `scene` 或 `manifest`，就不改。要改名時，舊 ID 放進 `aliases` 或 `deprecated_ids`。
- 角色、地點、素材的 ID 由人決定，不由程式自動產生中文轉拼音。
- 同一個中文名在不同書裡可以對應不同 ID，ID 只在 `book_id` 內唯一。

## 4. 輸入：novel-studio 書的格式（唯讀）

以 `示範小說` 為例，書目錄結構如下（中文資料夾與檔名是來源，程式只讀不改）：

| 來源路徑（相對書目錄） | 內容 | 讀取方式 |
|---|---|---|
| `正文/第NNN章_<章名>.md` | 正文，Markdown，標題 `# 第N章 <章名>` | 用 `第(\d+)章` 取章號，章名取標題 |
| `大綱/章綱/第NNN章.md` | 章綱（frontmatter＋情節點＋出場角色＋章末鉤子） | 經 `source_field_map.json` 轉 key |
| `大綱/全書大綱.md`、`大綱/卷綱_第N卷.md` | 全書與卷綱 | 第一版不用 |
| `設定/角色/<名稱>.md` | 角色卡（frontmatter＋外在／內在／聲音卡） | 經映射表轉 key；檔名不當 ID |
| `設定/勢力/*.md`、`設定/世界觀/*.md` | 勢力與世界觀 | 第一版不用 |
| `設定/名詞表.md` | 名詞表 | 讀入 `glossary.json` 作為一致性約束 |
| `追蹤/章節摘要/第NNN章.md` | 章節摘要 | 第一版只讀，做分場參考 |
| `追蹤/角色狀態/*.md`、`追蹤/狀態卡.md` | 角色狀態與狀態卡 | 第一版不用 |
| `正文/` 以外的 `候選/`、`.studio/` | 寫作過程暫存 | **不讀** |

### 4.1 來源 metadata 映射

來源檔頭是 YAML 風格，但 key 是中文（例：`類型: 章綱`、`章號: 001`）。轉換規則寫在 `config/source_field_map.json`：

```json
{
  "chapter_outline": {
    "類型": "doc_type",
    "章號": "chapter_no",
    "章名": "chapter_title",
    "所屬卷": "volume_title",
    "所屬單元": "arc_title",
    "字數目標": "word_target",
    "狀態": "status"
  }
}
```

- 映射表只在讀取層使用，轉換後的資料全部是英文 key。
- 來源檔值仍是中文（如 `doc_type` 的值 `章綱`），需要時也經映射（`"章綱": "chapter_outline"`）。
- 來源檔出現映射表沒有的欄位時，**報錯**，不要略過。這樣新欄位不會悄悄漏掉。

### 4.2 章綱的段落

| 來源段落（中文標題） | 轉換後的 key |
|---|---|
| `## 本章四問` | `four_questions` |
| `## 情節點` | `plot_points` |
| `## 出場角色` | `cast_names`（值是原文角色名，用 `aliases` 對到 `char_id`） |
| `## 章末鉤子` | `hook` |
| `## 禁止事項` | `forbidden` |

> 章綱的「禁止事項」是寫作限制，轉 VN 時要保留，驗證時檢查劇本沒有違反（例：第 1 章艾莉不能知道舊管線的存在）。

## 5. 輸出：資料檔結構

所有輸出放在 `works/<book_id>/`：

```
works/<book_id>/
├─ book.json            # 書的基本資料（1 個）
├─ cast.json            # 角色表（1 個）
├─ glossary.json        # 名詞表（1 個）
├─ chapters/
│  ├─ index.json        # 章節索引
│  ├─ ch001.json        # 正規化後的章節正文（段落編號），由 normalize_book.py 產生
│  └─ book.txt          # 給 ruxi scan_scenes.py 用的純文字（可選）
├─ scenes/
│  └─ ch001.json        # 每章的 scene graph（主要產出）
├─ manifest.json        # 素材需求清單（全書 1 個）
├─ assets/              # 素材（生成後才有）
│  ├─ bg/ sprite/ cg/ bgm/ ambience/ sfx/ ui/ fonts/
├─ build/               # 產生的 Ren'Py 專案（不進 git）
└─ out/                 # 打包輸出（不進 git）
```

### 5.1 `book.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "display_name": { "zh-TW": "示範小說" },
  "lang": "zh-TW",
  "source": {
    "book_library_key": "sample_book_dir",
    "dir_name": "示範小說"
  },
  "default_player_char": "ellie_reed"
}
```

- `source.dir_name` 是書目錄中的資料夾名，是值，允許中文。

### 5.2 `cast.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "characters": {
    "ellie_reed": {
      "names": { "zh-TW": "艾莉・里德" },
      "aliases": ["艾莉", "里德"],
      "role": "protagonist",
      "first_chapter": "ch001",
      "hue": 28,
      "shape": "small",
      "visual_tags": ["short_hair", "goggles"],
      "expressions": ["neutral", "smile", "worried", "angry"]
    }
  }
}
```

- `aliases` 用來對應台詞與章綱中的寫法；對應規則：任何 alias 都必須只對應一個 `char_id`。
- `role`：`protagonist`／`main`／`supporting`／`antagonist`／`minor`／`player`。
- `shape`、`hue` 沿用入戲的剪影格式（若第一版用剪影，不用真立繪）。

### 5.3 `glossary.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "terms": {
    "float_stone": {
      "names": { "zh-TW": "浮石" },
      "variants_forbidden": ["浮岩"],
      "note": "升力來源，全書統一寫法"
    }
  }
}
```

- `variants_forbidden` 列出不得出現的寫法；驗證時檢查正文與台詞。

詳細定義見 `schema/scene.schema.json`。結構摘要：

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "chapter_id": "ch001",
  "lang": "zh-TW",
  "source": {
    "file_key": "chapter_text",
    "paragraphs": [1, 20]
  },
  "scenes": [
    {
      "scene_id": "ch001_sc01",
      "title": { "zh-TW": "第一場・鐵皮棚頂" },
      "location_id": "scrapyard",
      "time_of_day": "dawn",
      "weather": "clear",
      "bg": { "asset_id": "bg_scrapyard_dawn" },
      "bgm": "bgm_workshop_daily",
      "ambience": "amb_wind_sea",
      "cast": [
        { "char_id": "ellie_reed", "expr": "neutral", "pos": "center" }
      ],
      "lines": [
        { "type": "narration", "text": "天還沒亮透，舊工坊的鐵皮棚頂先響了起來……", "source_para": 1 },
        { "type": "dialogue", "speaker": "ellie_reed", "expr": "neutral", "text": "好了，試一趟看看。", "source_para": 5 }
      ],
      "next": "ch001_sc02"
    }
  ]
}
```

### 5.5 `manifest.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "assets": [
    {
      "asset_id": "bg_scrapyard_dawn",
      "kind": "bg",
      "names": { "zh-TW": "舊工坊・清晨" },
      "file": "assets/bg/bg_scrapyard_dawn.png",
      "status": "planned",
      "spec": { "width": 1920, "height": 1080, "format": "png" },
      "prompt_en": "",
      "negative_prompt": "",
      "seed": null,
      "model": "",
      "loras": [],
      "license": "",
      "used_in": ["ch001_sc01"],
      "notes": ""
    }
  ]
}
```

- `kind`：`bg`、`sprite`、`headshot`、`cg`、`bgm`、`ambience`、`sfx`、`voice`、`ui`、`font`。`headshot`（頭像）：`assets/headshot/<char_id>_<expr>.png`，`expr` 為 neutral／smile／angry／sad／laughing；每個角色固定有 `sprite_<char_id>_neutral` 與 `headshot_<char_id>_neutral` 兩項（`used_in` 可為空）。
- `status`：`planned` → `generated` → `selected` → `processed` → `final`。
- `prompt_en`：出圖提示詞用英文（配合 Danbooru 標籤），不是台詞。
- `license`：必填，商用前要確認；空字串的素材不能進入發行版。

### 5.6 `chapters/ch001.json`（正規化章節）

由 `tools/normalize_book.py` 從書目錄的 `正文/` 產生。定義見 `schema/chapter.schema.json`；索引見 `schema/chapter_index.schema.json`。

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "chapter_id": "ch001",
  "chapter_no": 1,
  "title": "補囊",
  "source_file": "正文/第001章_補囊.md",
  "sha256": "<原始檔案 bytes 的 SHA-256>",
  "char_count": 3711,
  "paragraphs": [
    { "para_no": 1, "text": "天還沒亮透，舊工坊的鐵皮棚頂先響了起來……" }
  ],
  "scene_breaks": [24]
}
```

**段落規則**（`source_para` 的編號依據）：

1. 以 UTF-8 讀取（接受 BOM），換行統一成 `\n`。
2. 第一個非空行必須是章標題（`chapter_text_title_pattern`），否則報錯；章號必須和檔名一致。
3. 之後每個非空行（去掉前後空白，含全形空白）是一個段落，`para_no` 從 1 起算。
4. 只由 3 個以上 `* ＊ - — ◇ ◆ · ・` 組成的行是分場符號，不算段落；它後面第一個段落的編號記入 `scene_breaks`。
5. 以 `#` 開頭的小標題：去掉 `#` 後當段落，並在它之前記一個分場。
6. 正文中再出現章標題 → 報錯。
7. `char_count` 是所有段落去掉空白後的字元數。
8. `book.txt`（`--txt`）：開頭一個空行，每章是「`第N章`」獨占一行、章名一行、空行，然後每段一行、段與段之間空一行。開頭空行是因為 ruxi `scan_scenes.py` 只認換行後的章標題。

> 實測（《示範》第 1–5 章）：正文沒有分場符號，`scene_breaks` 全是空的，分場要靠 S4 判斷；最長段落 256 字，超過台詞上限 90 字，所以標註時一個段落要拆成多句，每句沿用同一個 `source_para`。

### 5.7 `prototype/`（HTML 原型，S3）

由 `python -m t2vn.prototype <scenes 檔> --work-dir works/<book_id>` 產生，引擎是 vendor 的 ruxi（入戲），格式說明見 `vendor/ruxi/script-schema.md`。

```
works/<book_id>/prototype/
├─ style.json     # 演出設定（人工維護）
├─ script.json    # ruxi 劇本（產生）
└─ index.html     # 單檔可玩原型（產生）
```

`style.json`（key 英文、值可中文）：`title`、`subtitle`、`version`、`credits`、`palette`（`bg`/`panel`/`text`/`dim`/`accent`）、`player`（`name`/`role`/`hue`/`shape`）、`labels`（`source_loc`、`source_loc_one`、`book_line`、`ending_title`、`ending_line`，可用 `{chapter_no}` `{title}` `{first}` `{last}`）、`locations`（`location_id` → `label`，可選 `c1`/`c2`）、`times`（`time_of_day` → `label`/`c1`/`c2`）。

轉換規則：

- `narration` → `who: null`；`dialogue` → `who: char_id`，`player` → ruxi 的 `me`；`direction` 原型略過；`choice` 尚未支援（作品第一版是 kinetic）。
- `expr` → ruxi `mood`：`neutral`/`serious` → `calm`；`smile`/`sad`/`embarrassed` → `soft`；`worried`/`surprised` → `tense`；`angry` → `hard`。
- 角色剪影用 `cast.json` 的 `hue`、`shape`（原型需要的角色都必須填）。
- 沒有分支時自動產生一個正典結局 `end_<chapter_id>`；`verdict` 為空。
- `pd_status` 用本專案新增的 `author-owned`。

### 5.8 `scenes/`（S4 自動標註）

由 `python -m t2vn.annotate --book <book_id> --chapters 2-5` 產生（先跑 `tools/normalize_book.py`）。

```
works/<book_id>/scenes/
├─ ch002.json          # scene graph（§5.4），通過 schema、連結、忠實度檢查才會寫出
├─ ch002_review.md     # 校對表（推斷的說話者標 ?、新角色提醒）
├─ _prompt/ch002.md    # --dry-run 時的提示詞（不進 git）
└─ _raw/ch002_r1.json  # 每一輪 LLM 原始回應（不進 git；失敗時用來除錯或 --replay 重跑）
```

- LLM 輸出精簡 op（`prompts/annotate_system.md`）：`N` 整段旁白（程式原文照抄、斷句）、`n` 旁白、`d` 台詞、`x` 演出；程式展開成 §5.4。
- 程式產生的欄位：`scene_id`、`next`、`bg.asset_id` = `bg_<location_id>_<time_of_day>`、`ambience` = `amb_<location_id>`、`source`。
- 檢查：每段都用到、段落順序不倒退、旁白與台詞的每個子句都能在原段落找到（允許句首補代名詞）、說話者在 `cast.json`、enum 合法、schema、連結；整段旁白（`N`）不可用在含說話引號的段落（會把台詞再念一次）；一場最多 35 段。有問題就把清單回給 LLM 修正（會附「這句話其實在第 X 段」之類的提示），最多 2 輪。
- LLM 提的新角色（`new_characters`）會加進 `cast.json`；角色卡有同名的用角色卡的定位，`hue`／`shape` 自動配。
- `config.yaml` 的 `llm`：`provider`、`model`（預設 `deepseek-flash`）、`thinking`（`off`/`low`/`high`/`max`）、`max_output`。另有選填 `works_dir`（作品存放位置，預設 `<project_root>/works`，可放在專案資料夾以外，但不能和唯讀的書庫互相包含）與 `server.port`（網頁介面埠號，預設 7866）。網頁的「設定」頁可以改這些，儲存時重寫 config.yaml 並備份成 `config.yaml.bak`。

### 5.9 校對／編輯介面（S4 後續）

網頁介面（`python -m t2vn.server`）新增或擴充的資料，所有 key 為英文：

- `book.json`：`source` 改為 `{"kind": "library", "dir_name": "<書庫資料夾>"}`（書庫書，章綱與角色卡從書庫唯讀讀取）或 `{"kind": "import", "files": ["b.epub"]}`（TXT／MD／DOCX／EPUB／貼上文字匯入）。舊檔的 `book_library_key` 仍可讀。書清單的唯一來源是 `works/*/book.json`，匯入的書不需要寫進 `config.yaml`。
- `cast.json` 的角色新增選填 `one_line`（`{語言: 一句話介紹}`），提示詞會當角色備註。
- `outlines/chNNN.json`（`schema/outline.schema.json`）：`summary`、`sections.plot_points`、`sections.cast_names`、`origin`（`llm_extract` 或 `manual`）。由 `t2vn.extract` 產生或手寫；標註時書庫章綱優先，缺的章用這裡的。
- `review_state.json`：`{"chapters": {"ch002": {"status": "draft|reviewed", "updated": "..."}}}`。沒有紀錄時，只有 `gold/` 的章視為 reviewed。
- 編輯時的場景檔：優先 `scenes/chNNN.json`，沒有才用 `gold/chNNN.json`；每次存檔先把舊版備份到同資料夾的 `_history/`（不進 git）。存檔時程式會重編 `scene_id`、修正 `next`、依地點與時段補 `bg.asset_id`、把說話者補進出場名單。
- 背景任務（標註、抽取）的進度由 `GET /api/jobs/active` 回報：逐章狀態、目前步驟（等待／串流字數／檢查／修正）、token、紀錄；`POST /api/jobs/<id>/stop` 可在模型串流途中中斷。
- 阻擋存檔的是 schema 與連結錯誤；「旁白找不到原文」「段落未使用」「段落順序倒退」只是提醒。

## 7. 驗證規則

資料檔寫入前必須通過以下檢查，任一失敗就不寫入：

| # | 檢查 | 說明 |
|---|---|---|
| V1 | JSON Schema | 結構、enum、ID 格式 |
| V2 | 角色存在 | `speaker`、`cast[].char_id` 都在 `cast.json` 裡 |
| V3 | 地點與素材存在 | `bg.asset_id` 等在 `manifest.json` 裡（生成前可為 `planned`） |
| V4 | 名詞一致 | 正文與台詞不含 `variants_forbidden` |
| V5 | 來源可追溯 | 每句 `dialogue`／`narration` 有 `source_para`（direction 除外） |
| V6 | 跳轉可達 | `next`、`choice.goto` 指向存在的 scene 或 end 節點 |
| V7 | 禁止事項 | 章綱「禁止事項」不被違反（人工覆核，程式只列出疑點） |
| V8 | 映射完整 | 來源檔沒有未映射的中文欄位 |

## 8. 版本與變更

- `schema_version` 目前是 `0.1`。破壞性變更（改名、刪欄、改 enum）升版本號，並在 `CHANGELOG.md` 記錄。
- 新增可選欄位不需要升版本號。
- 每個輸出檔都要帶 `schema_version`，讀取時先檢查，版本不符直接報錯。
