# 05 資料格式規格

> 版本：v1.0（2026-11-01）
> 狀態：**已確認**。之後的變更走版本號。
> 機器可讀定義：`schema/*.schema.json`、`config/source_field_map.json`

---

## 1. 範圍與原則

本文件定義三件事：

1. 目錄權限與路徑（什麼能讀、什麼能寫）
2. 命名規則（哪些地方必須英文，哪些地方可以中文）
3. 資料檔的結構（輸入來自 novel-studio 的書，輸出是 scene graph、角色表、素材清單）

### 1.1 三條硬規則

| # | 規則 | 原因 |
|---|---|---|
| R1 | 所有 key、ID、程式會讀的檔名與資料夾名只用 `[a-z0-9_]` | novel-studio 的問題：中文 key 讓跨語言工具難以處理，檔名編碼在 Windows 上也常出錯 |
| R2 | 顯示用文字可以是任何語言，但必須放在「值」或 `names`／`title` 這類 i18n 物件裡 | 之後加日文、英文不用改結構 |
| R3 | 書目錄唯讀；所有產出寫在 `works/<book_id>/` | 原稿不會被誤改 |

---

## 3. 命名規則

### 3.1 什麼要英文（key 層）

| 類別 | 規則 | 範例（對） | 範例（錯） |
|---|---|---|---|
| JSON/YAML 欄位名 | `^[a-z][a-z0-9_]*$` | `scene_id`, `time_of_day` | `場景ID`, `時間` |
| book_id | `^[a-z][a-z0-9_]{1,30}$` | `sample_book` | `示範`, `sample-book` |
| char_id | 同上 | `ellie_reed` | `艾莉`, `ellie`（同名多人時要有區分） |
| location_id | 同上 | `scrapyard` | `舊工坊` |
| scene_id | `^ch\d{3}_sc\d{2}$` | `ch001_sc03` | `第1章3場` |
| chapter_id | `^ch\d{3}$` | `ch001` | `第001章` |
| asset_id | 同 char_id | `bg_scrapyard_dawn` | `舊工坊_清晨` |
| enum 值 | 同上 | `dawn`, `tense` | `清晨`, `緊張` |
| 程式會讀的檔名 | 小寫＋底線 | `scene_ch001.json` | `第001章.json` |

### 3.2 什麼可以是中文（值層）

- `names`、`title`、`label`、`text`（台詞本文）等顯示用欄位。
- `aliases`（原文寫法，用來比對，例如 `"老張"`、`"老陳"`）。
- `source` 裡引用的原文路徑與段落說明。
- `docs/` 下的說明文件（中文檔名可以）。

### 3.3 i18n 物件

多語名稱統一寫法：

```json
"names": { "zh-TW": "艾莉・里德", "en": "Ellie Reed" }
```

- key 是 BCP-47 語言標籤（英文字元），value 是該語言的文字。
- 至少要有一個語言；`lang` 欄位（見 5.1）決定台詞本文的語言。
- 目前只做繁中，`en` 與 `ja` 之後再補；不要因此改結構。

### 3.4 ID 穩定性

- ID 一旦寫入 `scene` 或 `manifest`，就不改。要改名時，舊 ID 放進 `aliases` 或 `deprecated_ids`。
- 角色、地點、素材的 ID 由人決定，不由程式自動產生中文轉拼音。
- 同一個中文名在不同書裡可以對應不同 ID，ID 只在 `book_id` 內唯一。

## 4. 輸入：novel-studio 書的格式（唯讀）

以 `示範小說` 為例，書目錄結構如下（中文資料夾與檔名是來源，程式只讀不改）：

| 來源路徑（相對書目錄） | 內容 | 讀取方式 |
|---|---|---|
| `正文/第NNN章_<章名>.md` | 正文，Markdown，標題 `# 第N章 <章名>` | 用 `第(\d+)章` 取章號，章名取標題 |
| `大綱/章綱/第NNN章.md` | 章綱（frontmatter＋情節點＋出場角色＋章末鉤子） | 經 `source_field_map.json` 轉 key |
| `大綱/全書大綱.md`、`大綱/卷綱_第N卷.md` | 全書與卷綱 | 第一版不用 |
| `設定/角色/<名稱>.md` | 角色卡（frontmatter＋外在／內在／聲音卡） | 經映射表轉 key；檔名不當 ID |
| `設定/勢力/*.md`、`設定/世界觀/*.md` | 勢力與世界觀 | 第一版不用 |
| `設定/名詞表.md` | 名詞表 | 讀入 `glossary.json` 作為一致性約束 |
| `追蹤/章節摘要/第NNN章.md` | 章節摘要 | 第一版只讀，做分場參考 |
| `追蹤/角色狀態/*.md`、`追蹤/狀態卡.md` | 角色狀態與狀態卡 | 第一版不用 |
| `正文/` 以外的 `候選/`、`.studio/` | 寫作過程暫存 | **不讀** |

### 4.1 來源 metadata 映射

來源檔頭是 YAML 風格，但 key 是中文（例：`類型: 章綱`、`章號: 001`）。轉換規則寫在 `config/source_field_map.json`：

```json
{
  "chapter_outline": {
    "類型": "doc_type",
    "章號": "chapter_no",
    "章名": "chapter_title",
    "所屬卷": "volume_title",
    "所屬單元": "arc_title",
    "字數目標": "word_target",
    "狀態": "status"
  }
}
```

- 映射表只在讀取層使用，轉換後的資料全部是英文 key。
- 來源檔值仍是中文（如 `doc_type` 的值 `章綱`），需要時也經映射（`"章綱": "chapter_outline"`）。
- 來源檔出現映射表沒有的欄位時，**報錯**，不要略過。這樣新欄位不會悄悄漏掉。

### 4.2 章綱的段落

| 來源段落（中文標題） | 轉換後的 key |
|---|---|
| `## 本章四問` | `four_questions` |
| `## 情節點` | `plot_points` |
| `## 出場角色` | `cast_names`（值是原文角色名，用 `aliases` 對到 `char_id`） |
| `## 章末鉤子` | `hook` |
| `## 禁止事項` | `forbidden` |

> 章綱的「禁止事項」是寫作限制，轉 VN 時要保留，驗證時檢查劇本沒有違反（例：第 1 章艾莉不能知道舊管線的存在）。

## 5. 輸出：資料檔結構

所有輸出放在 `works/<book_id>/`：

```
works/<book_id>/
├─ book.json            # 書的基本資料（1 個）
├─ cast.json            # 角色表（1 個）
├─ glossary.json        # 名詞表（1 個）
├─ chapters/
│  ├─ index.json        # 章節索引
│  ├─ ch001.json        # 正規化後的章節正文（段落編號），由 normalize_book.py 產生
│  └─ book.txt          # 給 ruxi scan_scenes.py 用的純文字（可選）
├─ scenes/
│  └─ ch001.json        # 每章的 scene graph（主要產出）
├─ manifest.json        # 素材需求清單（全書 1 個）
├─ voice/               # 語音（S7；見 §5.10）
│  ├─ cast_voice.json   # 角色聲線設定（人工維護）
│  ├─ VoiceMap.json     # 每句台詞的語音結果
│  └─ refs/             # 參考音（含 Voice Design 產生的）
├─ assets/              # 素材（生成後才有）
│  ├─ bg/ sprite/ cg/ bgm/ ambience/ sfx/ voice/ ui/ fonts/
├─ build/               # 產生的 Ren'Py 專案（不進 git）
└─ out/                 # 打包輸出（不進 git）
```

### 5.1 `book.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "display_name": { "zh-TW": "示範小說" },
  "lang": "zh-TW",
  "source": {
    "book_library_key": "sample_book_dir",
    "dir_name": "示範小說"
  },
  "default_player_char": "ellie_reed"
}
```

- `source.dir_name` 是書目錄中的資料夾名，是值，允許中文。

### 5.2 `cast.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "characters": {
    "ellie_reed": {
      "names": { "zh-TW": "艾莉・里德" },
      "aliases": ["艾莉", "里德"],
      "role": "protagonist",
      "first_chapter": "ch001",
      "hue": 28,
      "shape": "small",
      "visual_tags": ["short_hair", "goggles"],
      "expressions": ["neutral", "smile", "worried", "angry"]
    }
  }
}
```

- `aliases` 用來對應台詞與章綱中的寫法；對應規則：任何 alias 都必須只對應一個 `char_id`。
- `role`：`protagonist`／`main`／`supporting`／`antagonist`／`minor`／`player`。
- `shape`、`hue` 沿用入戲的剪影格式（若第一版用剪影，不用真立繪）。

### 5.3 `glossary.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "terms": {
    "float_stone": {
      "names": { "zh-TW": "浮石" },
      "variants_forbidden": ["浮岩"],
      "note": "升力來源，全書統一寫法"
    }
  }
}
```

- `variants_forbidden` 列出不得出現的寫法；驗證時檢查正文與台詞。

### 5.4 `scenes/ch001.json`（scene graph）

詳細定義見 `schema/scene.schema.json`。結構摘要：

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "chapter_id": "ch001",
  "lang": "zh-TW",
  "source": {
    "file_key": "chapter_text",
    "paragraphs": [1, 20]
  },
  "scenes": [
    {
      "scene_id": "ch001_sc01",
      "title": { "zh-TW": "第一場・鐵皮棚頂" },
      "location_id": "scrapyard",
      "time_of_day": "dawn",
      "weather": "clear",
      "bg": { "asset_id": "bg_scrapyard_dawn" },
      "bgm": "bgm_workshop_daily",
      "ambience": "amb_wind_sea",
      "cast": [
        { "char_id": "ellie_reed", "expr": "neutral", "pos": "center" }
      ],
      "lines": [
        { "type": "narration", "text": "天還沒亮透，舊工坊的鐵皮棚頂先響了起來……", "source_para": 1 },
        { "type": "dialogue", "speaker": "ellie_reed", "expr": "neutral", "text": "好了，試一趟看看。", "source_para": 5 }
      ],
      "next": "ch001_sc02"
    }
  ]
}
```

### 5.5 `manifest.json`

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "assets": [
    {
      "asset_id": "bg_scrapyard_dawn",
      "kind": "bg",
      "names": { "zh-TW": "舊工坊・清晨" },
      "file": "assets/bg/bg_scrapyard_dawn.png",
      "status": "planned",
      "spec": { "width": 1920, "height": 1080, "format": "png" },
      "prompt_en": "",
      "negative_prompt": "",
      "seed": null,
      "model": "",
      "loras": [],
      "license": "",
      "used_in": ["ch001_sc01"],
      "notes": ""
    }
  ]
}
```

- `kind`：`bg`、`sprite`、`headshot`、`cg`、`bgm`、`ambience`、`sfx`、`voice`、`ui`、`font`。`headshot`（頭像）：`assets/headshot/<char_id>_<expr>.png`，`expr` 為 neutral／smile／angry／sad／laughing；每個角色固定有 `sprite_<char_id>_neutral` 與 `headshot_<char_id>_neutral` 兩項（`used_in` 可為空）。
- `status`：`planned` → `generated` → `selected` → `processed` → `final`。
- `prompt_en`：出圖提示詞用英文（配合 Danbooru 標籤），不是台詞。
- `license`：必填，商用前要確認；空字串的素材不能進入發行版。

### 5.6 `chapters/ch001.json`（正規化章節）

由 `tools/normalize_book.py` 從書目錄的 `正文/` 產生。定義見 `schema/chapter.schema.json`；索引見 `schema/chapter_index.schema.json`。

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "chapter_id": "ch001",
  "chapter_no": 1,
  "title": "補囊",
  "source_file": "正文/第001章_補囊.md",
  "sha256": "<原始檔案 bytes 的 SHA-256>",
  "char_count": 3711,
  "paragraphs": [
    { "para_no": 1, "text": "天還沒亮透，舊工坊的鐵皮棚頂先響了起來……" }
  ],
  "scene_breaks": [24]
}
```

**段落規則**（`source_para` 的編號依據）：

1. 以 UTF-8 讀取（接受 BOM），換行統一成 `\n`。
2. 第一個非空行必須是章標題（`chapter_text_title_pattern`），否則報錯；章號必須和檔名一致。
3. 之後每個非空行（去掉前後空白，含全形空白）是一個段落，`para_no` 從 1 起算。
4. 只由 3 個以上 `* ＊ - — ◇ ◆ · ・` 組成的行是分場符號，不算段落；它後面第一個段落的編號記入 `scene_breaks`。
5. 以 `#` 開頭的小標題：去掉 `#` 後當段落，並在它之前記一個分場。
6. 正文中再出現章標題 → 報錯。
7. `char_count` 是所有段落去掉空白後的字元數。
8. `book.txt`（`--txt`）：開頭一個空行，每章是「`第N章`」獨占一行、章名一行、空行，然後每段一行、段與段之間空一行。開頭空行是因為 ruxi `scan_scenes.py` 只認換行後的章標題。

> 實測（《示範》第 1–5 章）：正文沒有分場符號，`scene_breaks` 全是空的，分場要靠 S4 判斷；最長段落 256 字，超過台詞上限 90 字，所以標註時一個段落要拆成多句，每句沿用同一個 `source_para`。

### 5.7 `prototype/`（HTML 原型，S3）

由 `python -m t2vn.prototype <scenes 檔> --work-dir works/<book_id>` 產生，引擎是 vendor 的 ruxi（入戲），格式說明見 `vendor/ruxi/script-schema.md`。

```
works/<book_id>/prototype/
├─ style.json     # 演出設定（人工維護）
├─ script.json    # ruxi 劇本（產生）
└─ index.html     # 單檔可玩原型（產生）
```

`style.json`（key 英文、值可中文）：`title`、`subtitle`、`version`、`credits`、`palette`（`bg`/`panel`/`text`/`dim`/`accent`）、`player`（`name`/`role`/`hue`/`shape`）、`labels`（`source_loc`、`source_loc_one`、`book_line`、`ending_title`、`ending_line`，可用 `{chapter_no}` `{title}` `{first}` `{last}`）、`locations`（`location_id` → `label`，可選 `c1`/`c2`）、`times`（`time_of_day` → `label`/`c1`/`c2`）。

轉換規則：

- `narration` → `who: null`；`dialogue` → `who: char_id`，`player` → ruxi 的 `me`；`direction` 原型略過；`choice` 尚未支援（作品第一版是 kinetic）。
- `expr` → ruxi `mood`：`neutral`/`serious` → `calm`；`smile`/`sad`/`embarrassed` → `soft`；`worried`/`surprised` → `tense`；`angry` → `hard`。
- 角色剪影用 `cast.json` 的 `hue`、`shape`（原型需要的角色都必須填）。
- 沒有分支時自動產生一個正典結局 `end_<chapter_id>`；`verdict` 為空。
- `pd_status` 用本專案新增的 `author-owned`。

### 5.8 `scenes/`（S4 自動標註）

由 `python -m t2vn.annotate --book <book_id> --chapters 2-5` 產生（先跑 `tools/normalize_book.py`）。

```
works/<book_id>/scenes/
├─ ch002.json          # scene graph（§5.4），通過 schema、連結、忠實度檢查才會寫出
├─ ch002_review.md     # 校對表（推斷的說話者標 ?、新角色提醒）
├─ _prompt/ch002.md    # --dry-run 時的提示詞（不進 git）
└─ _raw/ch002_r1.json  # 每一輪 LLM 原始回應（不進 git；失敗時用來除錯或 --replay 重跑）
```

- LLM 輸出精簡 op（`prompts/annotate_system.md`）：`N` 整段旁白（程式原文照抄、斷句）、`n` 旁白、`d` 台詞、`x` 演出；程式展開成 §5.4。
- 程式產生的欄位：`scene_id`、`next`、`bg.asset_id` = `bg_<location_id>_<time_of_day>`、`ambience` = `amb_<location_id>`、`source`。
- 檢查：每段都用到、段落順序不倒退、旁白與台詞的每個子句都能在原段落找到（允許句首補代名詞）、說話者在 `cast.json`、enum 合法、schema、連結；整段旁白（`N`）不可用在含說話引號的段落（會把台詞再念一次）；一場最多 35 段。有問題就把清單回給 LLM 修正（會附「這句話其實在第 X 段」之類的提示），最多 2 輪。
- LLM 提的新角色（`new_characters`）會加進 `cast.json`；角色卡有同名的用角色卡的定位，`hue`／`shape` 自動配。
- `config.yaml` 的 `llm`：`provider`、`model`（預設 `deepseek-flash`）、`thinking`（`off`/`low`/`high`/`max`）、`max_output`。另有選填 `works_dir`（作品存放位置，預設 `<project_root>/works`，可放在專案資料夾以外，但不能和唯讀的書庫互相包含）與 `server.port`（網頁介面埠號，預設 7866）。網頁的「設定」頁可以改這些，儲存時重寫 config.yaml 並備份成 `config.yaml.bak`。

### 5.9 校對／編輯介面（S4 後續）

網頁介面（`python -m t2vn.server`）新增或擴充的資料，所有 key 為英文：

- `book.json`：`source` 改為 `{"kind": "library", "dir_name": "<書庫資料夾>"}`（書庫書，章綱與角色卡從書庫唯讀讀取）或 `{"kind": "import", "files": ["b.epub"]}`（TXT／MD／DOCX／EPUB／貼上文字匯入）。舊檔的 `book_library_key` 仍可讀。書清單的唯一來源是 `works/*/book.json`，匯入的書不需要寫進 `config.yaml`。
- `cast.json` 的角色新增選填 `one_line`（`{語言: 一句話介紹}`），提示詞會當角色備註。
- `outlines/chNNN.json`（`schema/outline.schema.json`）：`summary`、`sections.plot_points`、`sections.cast_names`、`origin`（`llm_extract` 或 `manual`）。由 `t2vn.extract` 產生或手寫；標註時書庫章綱優先，缺的章用這裡的。
- `review_state.json`：`{"chapters": {"ch002": {"status": "draft|reviewed", "updated": "..."}}}`。沒有紀錄時，只有 `gold/` 的章視為 reviewed。
- 編輯時的場景檔：優先 `scenes/chNNN.json`，沒有才用 `gold/chNNN.json`；每次存檔先把舊版備份到同資料夾的 `_history/`（不進 git）。存檔時程式會重編 `scene_id`、修正 `next`、依地點與時段補 `bg.asset_id`、把說話者補進出場名單。
- 背景任務（標註、抽取）的進度由 `GET /api/jobs/active` 回報：逐章狀態、目前步驟（等待／串流字數／檢查／修正）、token、紀錄；`POST /api/jobs/<id>/stop` 可在模型串流途中中斷。
- 阻擋存檔的是 schema 與連結錯誤；「旁白找不到原文」「段落未使用」「段落順序倒退」只是提醒。

### 5.10 `voice/`（S7 語音）

規格見 `docs/33_語音管線規格.md`；schema 是 `schema/cast_voice.schema.json`、`schema/voice_map.schema.json`。

- **line_id**：scene graph 沒有內建行號，語音用 `line_id = <scene_id>_l<3 位行號>`，行號是該場 `lines` 的 1 起算位置（含 narration／direction）。`t2vn.voice_lines.line_id()` 是唯一產生方式，匯出器與語音產生器共用。
- **`voice/cast_voice.json`**：每個角色一個聲線，`source` 四選一：
  `reference_audio`（`reference_audio` 指 3–10 秒參考音）、`voice_design_prompt`（`voice_design_prompt` 自然語言描述）、`design_then_clone`（先設計參考音再克隆）、`speaker_id`（sherpa-onnx 預訓練模型的固定 speaker）。選填 `seed`、`language`、取樣參數、`speaker_id`、`speed`、`enabled`；`engine` 可為 `moss-tts-local-1.7b`／`moss-tts-delay-8b`／`moss-voicegenerator-1.7b`／`sherpa-onnx`。
- **`voice/VoiceMap.json`**：以 line_id 為 key，記錄 `speaker`、`chapter`、`scene_id`、`text`、`audio`（`game/audio/voice/...`）、`file`（Ren'Py 用）、`work_file`、`source`、`engine`、`seed`、`text_hash`、`config_hash`、長度與取樣率；`designs` 記錄 `design_then_clone` 的參考音。同一 line_id 重新生成時 `seed` 不變；`text_hash`／`config_hash` 不同就重新生成。
- **音檔**：`assets/voice/<chapter>/<speaker>_<line_id>.ogg`（OGG Vorbis、24 kHz、單聲道）；匯出時複製到 `game/audio/voice/<chapter>/`，並在對白前插入 `voice "audio/voice/<chapter>/<speaker>_<line_id>.ogg"`。
- 沒有 `voice/cast_voice.json` 或 `VoiceMap.json` 時，匯出器行為與舊版相同；`--no-voice` 可強制關閉。

### 5.11 `comic/`（漫畫專案，I4）

漫畫專案由 vendored 的 `t2c`（text2comics 的 `t2c/` 套件，來源見 `vendor/t2c/VENDORED.md`）建立與讀寫，目錄就放在書的資料夾裡：

```
works/<book_id>/comic/<project_id>/
├── project.yaml                t2c 的專案設定（title、style_preset、candidates…）
├── settings.json               宿主寫的嵌字設定（D12；只覆寫有寫的鍵）
├── cast_placeholders.json      t2vn 產生：哪些角色卡是佔位
├── bible/characters/*.md       角色卡（frontmatter 要有 id，以及 look_en 或 sections）
├── bible/locations/*.md        地點卡（規則同上）
├── source/chNNN.txt            原著章節正文，由 chapters/chNNN.json 寫來
├── storyboard/chNNN.json       分鏡
├── bible/characters/<id>.md    定案角色卡（t2c 格式；由 t2vn 轉換寫入，見 5.11.3）
├── bible/locations/<id>.md     定案地點卡（同上）
├── bible/drafts/<kind>/<id>.md 檢查沒過的草稿（t2c 只讀定案目錄，草稿不影響 project）
├── letters/chNNN.json          逐句嵌字微調（由 t2vn 的介面寫入，見 5.11.1）
└── pages/ renders/ picks/ out/     t2c 的產出（不由 t2vn 寫）
```

- **識別方式**：書由目錄位置決定、章由 `source/chNNN.txt` 決定，**不新增 `schema/` 欄位**（決策 D2）。
- **`project_id`**：`^[a-z][a-z0-9_]{1,30}$`，與 `book_id` 同一條規則；不合就擋下，順便擋掉 `../x` 這種路徑穿越。
- **`cast_placeholders.json`**：`{book_id, project_id, characters, written, kept, placeholder[], skipped_ids[]}`。`placeholder` 是沒有外觀卡、或卡片沒有 `sprite_prompt` 的角色；`skipped_ids` 是 id 不合 t2c 的 `^[a-z0-9_-]+$` 而被跳過的角色（寫進去會讓整個專案開不起來）。
- **`source/chNNN.txt` 格式**：第一行 `# 第N章 章名`、空一行、其後一段一行、段落之間空行。用 `t2c.annotate.split_paragraphs()` 讀回來的段落必須與 `chapters/chNNN.json` 的 `paragraphs` 逐段相同。它會略過 Markdown 標題行與分隔線，所以寫入端不得產生那種行；`t2vn.comic.write_source()` 寫完會自己比對一次，不同就丟錯。
- **角色卡與地點卡（5.11.3）**：由 `t2vn` 轉換寫入，規則見 `docs/37_資源共用規格.md`。人工值放在外觀卡的 `t2c` 子物件（D26），**不再**把 `sprite_prompt` 直接當 `look_en`。沒有外觀卡的角色寫 `unidentified adult, plain clothes` 並標 `placeholder: true`（D10）。卡已經存在時預設不覆蓋，要換掉得明寫 `overwrite=True`。
 同一張卡只留一個實體（D28）：寫進定案目錄時 `drafts/` 的同 id 舊檔會刪掉，寫進 `drafts/` 時定案目錄那份會刪掉，所以清單不會出現同一張卡的兩列。
- **寫入守門只做一半**：只有「建立專案」那一刻過 `Config.assert_writable`；專案內的檔案由 t2c 自己寫，宿主攔不到。例外是 `letters/chNNN.json` 與 `settings.json`（宿主介面寫的），寫檔前會自己過一次 `assert_writable`。所以不要宣稱「所有寫入都經 assert_writable」（決策 D2）。讀取端一律走 `t2vn.comic.assert_inside()`：解析後必須仍在該專案資料夾之內。
- **`settings.json`（宿主寫，D12）**：`{"lettering": {dialogue_font, shout_font, narration_font, sfx_font, vertical, dialogue_pt, narration_pt}}`。只覆寫有寫的鍵；空字串或 `null` 等於刪掉該鍵、回到自動尋找。字型值是路徑，TTC 可以用 `檔名#索引`。寫檔前過 `Config.assert_writable`。
- **字型與授權**：只有 OFL 字型（Noto Sans TC、Noto Serif TC）可以隨成品發佈；Windows 內建的 `msjh`／`msjhbd`／`mingliu` 只供自己看。字型檔不進 git，`settings.json` 只記本機路徑。設定卡與 `docs/HANDOFF.md` 各有一份清單。
- **可變字型的字重**：Pillow 讀字型不套可變軸，`NotoSansTC-VF.ttf` 的預設實例是 wght 100（Thin）。宿主用 `t2vn.comic.lettering_settings()` 包一層 t2c 的 `Settings`，在 `font()` 之後依角色套字重：dialogue 用 Regular、narration 用 Medium、shout 與 sfx 用 Black。靜態字型沒有可變軸，行為不變。
- 這一節的檔案格式由 t2c 定義，以 vendored 的程式為準。唯一例外是 `letters/chNNN.json`：宿主介面會寫它，所以有一個宿主側的 schema（`schema/letters.schema.json`，見 5.11.1）；t2c 的 `letter.check_letters()` 仍是最終驗證。
- 程式：`t2vn/comic.py`（薄包裝）。漫畫的任務、端點與介面在 I4-C／I4-E 之後才有。

### 5.11.1 `letters/chNNN.json`（逐句嵌字微調）

`letters/chNNN.json` 是人為微調的唯一入口；檔案不存在＝全部自動。座標一律相對於「裁切後看到的格子」（`plan_page()` 的 `rect`），不是整頁。

**頂層**

| 欄位 | 型別 | 範圍 | 說明 |
|---|---|---|---|
| `version` | int | 1 | t2c 的 `LETTERS_VERSION`，不是 `schema_version` |
| `chapter` | int | 1–999 | 寫回用；讀取端不驗 |
| `panels` | object | panel id → 一格的微調 | 沒有微調的格不要寫 |

- panel id 是 `pNNN_kN`（t2c 一律用預設 id：頁碼三位、格號不補零）。`PUT` 會擋不在分鏡裡的 id。
- 讀取端允許 `_` 開頭的註解鍵（t2c 會跳過），schema 也放行。

**每格**

| 欄位 | 型別 | 範圍 | 說明 |
|---|---|---|---|
| `faces` | array 或 null | 每框 `[x0, y0, x1, y1]`，4 個 0–1 | `null`／省略＝自動推估；`[]`＝不避開任何臉 |
| `bubbles` | array | 依分鏡的順序 | 第 i 個元素對應第 i 個對話框；不改的寫 `{}` 或 `null`，不能跳過順序 |
| `sfx` | array | 依分鏡的順序 | 狀聲詞；元素是 `{box, angle, vertical}` |

**對話框（`bubbles[i]`）**

| 欄位 | 型別 | 範圍 | 說明 |
|---|---|---|---|
| `text` | string | 任意 | 覆寫台詞；與分鏡不同時，組版會回「台詞改過了」提醒 |
| `center` | `[x, y]` | 0–1，相對格框 | 對話框中心；省略＝自動選位 |
| `tail` | `[x, y]` 或 null | 0–1，相對格框 | 省略＝自動接臉；`null`＝不畫尾巴（旁白與廣播本來就沒有） |
| `scale` | number | 0.5–2.0 | 字級倍率；放不下時 t2c 仍會再縮（`FIT_SCALES`） |
| `rows` | int | 1–40 | 每欄行數；省略＝自動 |

**狀聲詞（`sfx[i]`）**

| 欄位 | 型別 | 範圍 | 說明 |
|---|---|---|---|
| `box` | `[x0, y0, x1, y1]` | 4 個 0–1，`x0 < x1`、`y0 < y1` | 省略＝用分鏡的比例框 |
| `angle` | number | ±45 | 旋轉角度 |
| `vertical` | bool | true／false | 直排 |

- **框型不在這個檔案**：`speech`／`thought`／`shout`／`whisper`／`radio`／`narration` 是分鏡的 `bubble.kind`；letters 只覆寫位置與字，`plan_page()` 會把 `kind` 一起回給介面。六個值同時列在第 6 節。
- **寫檔正規化**（`t2c.letter.save_letters()`）：panel id 排序、空的一格不寫、尾端空的 bubble／sfx 元素去掉、座標四捨五入 4 位、座標寫成一行、檔尾換行。
- **`PUT …/letters` 是整份取代**：body 是 `{"panels": {...}}`；沒帶到的格會從檔案消失。介面每次送完整的 `panels`（包含沒改的 `faces`／`sfx`）。
- **驗證**：先過 t2c 的 `check_letters()`（欄位、範圍、座標），再過 `schema/letters.schema.json`；panel id 必須在該章分鏡裡。讀取沒有檔案回空 `{}`，不算錯。
- **宿主端點**：`GET …/chapter/{n}/letters` 回 `{chapter, exists, panels, path}`；`GET …/chapter/{n}/letters/plan?page=N` 回 `{chapter, page, pages: [plan_page 的結果]}`。

### 5.11.2 `out/`（PDF 與 CBZ）

`out/chNNN.pdf` 與 `out/chNNN.cbz` 由 t2c 的 `export` 產生；宿主只提供 metadata，形狀同 t2c 的 `export.default_meta()`（`t2vn.comic.export_meta()`）。

| CBZ 的 `ComicInfo.xml` | 值 |
|---|---|
| `Title` | 分鏡的 `title`（章名）；分鏡不在時是「書名　第 N 章」 |
| `Series` | `project.yaml` 的 `title`（書名） |
| `Number` | 章號 |
| `PageCount` | ZIP 內實際的頁面 PNG 數 |
| `Manga` | 固定 `YesAndRightToLeft` |

`ComicInfo.xml` 是 ZIP 的成員（`ComicInfo.xml`，開頭大寫），不是書目錄裡的資料檔，所以沒有 schema；PDF 的 `/Title` 用同一個 `title`。

### 5.11.3 `bible/`（角色卡與地點卡）

由 `t2vn.comic.bible_cards()` 轉換寫入（端點 `POST …/comic/{project}/bible`）；格式以 `vendor/t2c` 的 `project.py`（載入）與 `bible_check.check_card()`（驗證）為準。規則見 `docs/37_資源共用規格.md`。

| 來源 | 產出 | 說明 |
|---|---|---|
| `art/appearance/<id>.json` 的 `t2c.sections`／`t2c.outfits` | `bible/characters/<id>.md` | 人工確認過的值，優先使用 |
| 同一張卡的兩個提示詞（沒有 `t2c` 時） | `bible/drafts/characters/<id>.md` | 文字規則粗拆的草稿，一定還要人看 |
| `art/style.json` 的 `locations.<id>.description` | `bible/locations/<id>.md` | `look_en` 用英文段落，不用 tags |
| `manifest.json` 的 bg 名稱 | 地點卡的 `name` | 拆「・」前面那段（`bg_scrapyard_dawn` → 舊工坊） |
| `cast.json` 的 `names`／`aliases` | 角色卡的 `name`／`aliases` | `names` 取 `zh-TW`，沒有才退 `en` |

- **寫入守門**：寫檔前後都跑 `check_card()`；**0 error 才進 `bible/<kind>/`**，有 error 寫進 `bible/drafts/<kind>/` 並把每一條回給呼叫端。
- **佔位卡的例外**：沒有外觀卡的角色照 D10 寫進定案目錄（`look_en` 是 `unidentified adult, plain clothes`）。它是「還沒畫的角色」，不是「不合規的卡」；擋掉會讓整章不能標註。
- **`placeholder: true`（宿主標記，t2c 不讀）**：佔位卡的 frontmatter 由 `t2vn/comic.py` 在 `render_card` 之後補這一行——vendor 的 `render_card` 不寫它，而 `vendor/t2c` 不可改（`sync_t2c` 會判漂移）。`GET …/bible` 的每一列因此回 `placeholder`，清單分得開「還沒畫」與「不合規」。t2c 自己的分段編輯器重寫卡時會掉這一行（T2VN 不知道 t2c 改過卡，規格 §8）。
- **心聲 id 不寫卡**：`art_cards.SKIP_CHARACTERS`（目前只有 `player`）不產生角色卡，回在 `skipped_characters` 與 `cast_placeholders.json`；它不進分鏡的角色名單（`t2vn/annotate.py:270`）。
- **不覆蓋**：定案卡或草稿已經存在就不動（要看舊卡的問題用 `GET …/bible`）。
- **過期提醒**：`t2c.source_sha1` 與 `appearance_card.prompt_fingerprint()` 對不上 → 回在 `stale` 清單，不擋寫入。

## 8. 版本與變更
