# 33 語音管線規格（sherpa-onnx 優先；MOSS-TTS／ComfyUI 選用）

> 版本：v0.2（2026-11-03）　狀態：**已實作**。預設語音後端：**sherpa-onnx**（CPU、固定 speaker id）；
> MOSS-TTS＋ComfyUI 保留為實驗／真人參考音 Clone。實作：`t2vn/voice_lines.py`、`voice_workflow.py`、
> `sherpa_tts.py`、`voice_gen.py`、`export_renpy.py`、`server.py`。
> 模型清單：`docs/34_sherpa模型清單.md`；使用者版快速開始：`docs/36_語音快速開始.md`。
> 規則來源：`docs/05`（命名、scene graph）；`docs/30`（Ren'Py 匯出）。

## 1. 範圍

把 scene graph 的**對白**批次轉成語音檔，寫出 `VoiceMap.json`，並在 Ren'Py 匯出時插入
`voice "audio/voice/<chapter>/<speaker>_<line_id>.ogg"`。

- v1 只做**對白**（`type: dialogue`）；旁白預設不配音。玩家內心獨白（`speaker: player`）只有在
  `cast_voice.json` 明確設定時才配音。
- 語音是**可選模組**：沒有 `voice/cast_voice.json` 或 `voice/VoiceMap.json` 時，匯出器行為與以前完全相同。
- 不在本規格內：即時語音、多語配音、對嘴、情緒標籤自動推論。語音頁在 `ui/page_voice.js`。

## 2. 流程

```
scene graph（scenes/ 或 gold/）
   │  穩定 line_id：<scene_id>_l<3 位行號>
   ▼
voice/cast_voice.json（每個角色四選一的聲線）
   │  speaker_id（sherpa-onnx，預設） / reference_audio / voice_design_prompt / design_then_clone
   ▼
/tts/generate（或 python -m t2vn.voice_gen）
   │  speaker_id → sherpa-onnx（CPU，不需 ComfyUI）
   │  其他      → ComfyUI HTTP API + MOSS-TTS 節點
   ▼
assets/voice/<chapter>/<speaker>_<line_id>.ogg   ← ffmpeg 轉 OGG Vorbis
voice/VoiceMap.json
   ▼
export_renpy → game/audio/voice/... + voice 語句
```

## 3. 資料

### 3.1 line_id

scene graph 沒有內建 `line_id`。本管線用**確定性**規則產生：

```
line_id = "<scene_id>_l<index>"
例：ch001_sc02 的第 3 行 → ch001_sc02_l003
```

- `index` 是該場 `lines` 陣列的 1 起算位置（含 narration、direction；這樣插入任何一行都只影響
  它後面的 id）。
- 格式：`^ch[0-9]{3}_sc[0-9]{2}_l[0-9]{3}$`。
- 匯出器與語音產生器共用 `t2vn.voice_lines.iter_lines()`，不得各自實作一套。
- 排版/校對若在中間插入台詞，後面的 line_id 會改變；這在 `VoiceMap.json` 是可見的（舊條目留在
  檔案裡，重新產生時會被忽略）。不要手動改 line_id。

### 3.2 `voice/cast_voice.json`

位置：`works/<book_id>/voice/cast_voice.json`（舊位置 `works/<book_id>/cast_voice.json` 仍可讀，
寫入一律寫新位置）。Schema：`schema/cast_voice.schema.json`；可直接參考
`config/cast_voice.example.json`（MOSS）或 `config/cast_voice.sherpa.example.json`（sherpa）修改。

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "engine": "moss-tts-local-1.7b",
  "characters": {
    "ellie_reed": {
      "source": "reference_audio",
      "reference_audio": "refs/ellie_reed.wav",
      "seed": 4217,
      "language": "zh"
    },
    "lao_zhang": {
      "source": "voice_design_prompt",
      "voice_design_prompt": "一位低沉、緩慢、略帶沙啞的中年男性，說中文，語速偏慢。",
      "seed": 9173,
      "language": "zh",
      "max_new_tokens": 256
    }
  }
}
```

每個角色**必須**有 `source`，四選一：

| `source` | 必要欄位 | 行為 |
|---|---|---|
| `reference_audio` | `reference_audio` | 上傳 3–10 秒乾淨人聲到 ComfyUI，用 Voice Clone 逐句生成。**不需要逐字稿。** |
| `voice_design_prompt` | `voice_design_prompt` | 每一句都用 Voice Design 直接生成；同一角色固定同一 `seed` 與描述。**本機實測這個模式比 Clone 穩，沒有克隆雜音。** |
| `design_then_clone` | `voice_design_prompt` | 先用 Voice Design 產生一段參考音（`design_text`，預設一句固定台詞），存到 `refs/<char_id>_design.flac`，再逐句 Voice Clone。可重複使用同一段參考音；但用合成參考音克隆在本機可能出現雜音／不像中文，建議先試 `voice_design_prompt`。 |
| `speaker_id` | `speaker_id` | 用 **sherpa-onnx** 的預訓練多人模型，固定一個 speaker id；不需要參考音、不需要 ComfyUI，CPU 可跑。**目前《示範》艾莉＝20、老張＝100。** |

選填欄位：

| 欄位 | 說明 |
|---|---|
| `design_reference` | `design_then_clone` 專用；已存在的設計參考音（相對 `voice/`）。有給就不重新設計。 |
| `design_text` | 設計參考音要唸的文字；預設見 `voice_lines.DEFAULT_DESIGN_TEXT`。 |
| `speaker_id` | `speaker_id` 專用；sherpa-onnx 模型的 speaker 編號（0 起算）。 |
| `speed` | sherpa-onnx 語速，0.5–2.0，預設 1.0。 |
| `sherpa_model` | `cast_voice.json` 最上層選填；模型資料夾（相對專案根目錄），預設 `models/sherpa/vits-zh-hf-fanchen-C`。 |
| `seed` | 角色基準種子（0–2^31−1）。沒給時由 `char_id` 的 CRC32 決定。 |
| `language` | `auto`／`zh`／`en`／`ja`／`ko`，預設 `zh`。 |
| `temperature`、`top_p`、`top_k`、`repetition_penalty`、`max_new_tokens` | 覆寫 MOSS 取樣參數；沒給用模型建議值。 |
| `enabled` | `false` 時這個角色不配音（預設 `true`）。 |
| `note` | 給人看的備註。 |

`reference_audio` 路徑解析順序：絕對路徑 → `works/<book>/voice/<路徑>` → `works/<book>/<路徑>`。
建議放 `voice/refs/`。檔案必須是 `.wav`／`.flac`／`.ogg`／`.opus`／`.mp3`。

《示範》目前的 sherpa-onnx 設定（艾莉 2、老張 100；模型 `vits-zh-hf-theresa`）：

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "engine": "sherpa-onnx",
  "sherpa_model": "models/sherpa/vits-zh-hf-theresa",
  "characters": {
    "ellie_reed": { "source": "speaker_id", "speaker_id": 2, "speed": 1.0 },
    "lao_zhang": { "source": "speaker_id", "speaker_id": 100, "speed": 1.0 }
  }
}
```

sherpa-onnx 的模型與套件是選配：`pip install -r requirements-tts.txt`；模型放
`models/sherpa/vits-zh-hf-fanchen-C/`。`models/` 不進 git。

### 3.3 `voice/VoiceMap.json`

Schema：`schema/voice_map.schema.json`。**以 line_id 為 key**；每一筆記錄聲線來源、引擎、種子、
文字雜湊與輸出路徑，用來判斷是否可以跳過重新生成。

```json
{
  "schema_version": "0.1",
  "book_id": "sample_book",
  "engine": "moss-tts-local-1.7b",
  "updated": "2026-11-03T15:00:00+08:00",
  "lines": {
    "ch001_sc02_l003": {
      "line_id": "ch001_sc02_l003",
      "speaker": "ellie_reed",
      "chapter": "ch001",
      "scene_id": "ch001_sc02",
      "text": "你終於來了。",
      "audio": "game/audio/voice/ch001/ellie_reed_ch001_sc02_l003.ogg",
      "file": "audio/voice/ch001/ellie_reed_ch001_sc02_l003.ogg",
      "work_file": "assets/voice/ch001/ellie_reed_ch001_sc02_l003.ogg",
      "source": "reference_audio",
      "engine": "moss-tts-local-1.7b",
      "seed": 4217,
      "text_hash": "b7e2…",
      "config_hash": "1d9c…",
      "duration": 1.85,
      "sample_rate": 24000,
      "created": "2026-11-03T14:58:00+08:00"
    }
  }
}
```

- `audio` 是「遊戲資料夾」路徑（`game/audio/...`），給人看與驗收用；`file` 是 Ren'Py `voice`
  語句實際用的相對路徑；`work_file` 是作品資料夾內的來源檔。
- 同一 line_id 重新生成時 `seed` 不變。`config_hash` 含聲線設定、參考音內容雜湊與取樣參數；
  只要其中一項變了就會重新生成。
- `designs`（選填）記錄 `design_then_clone` 的參考音：`file`、`seed`、`config_hash`、`created`。
  描述或種子改了，`config_hash` 不同就會重新設計；只有相同才重用既有參考音。
- 單句失敗不會寫入 VoiceMap，也不會刪掉舊的成功條目。

### 3.4 音檔

- 格式：**OGG Vorbis**（`.ogg`），ffmpeg `libvorbis`，24 kHz、單聲道、`-q:a 4`（約 96 kbps）。
- 響度：`loudnorm=I=-16:TP=-1.5:LRA=11`（語音比 BGM 大聲一點）。
- 頭尾靜音：先用 `silenceremove` 去掉開頭／結尾的靜音（-45 dB、至少 0.05 秒；中間停頓保留），
  再做響度正規化。MOSS Voice Design 對短句常在頭尾各生成 2–3 秒空白，不修剪時「四個字」會變成
  四秒；`voice_ffmpeg.convert_command(trim_silence=False)` 可關閉。
- 路徑：`works/<book>/assets/voice/<chapter>/<speaker>_<line_id>.ogg`。
- 匯出時複製到 `<project>/game/audio/voice/<chapter>/<speaker>_<line_id>.ogg`。
- ComfyUI 的 `SaveAudio` 先存 FLAC，**一定**經過 ffmpeg 轉檔；不直接把 ComfyUI 的輸出當成品。

## 4. ComfyUI 與模型

### 4.1 節點包

預設 [`richservo/comfyui-moss-tts`](https://github.com/richservo/comfyui-moss-tts)：

```
I:\ComfyUI\custom_nodes\comfyui-moss-tts
```

節點（class_type）：

| 節點 | class_type | 用途 |
|---|---|---|
| MOSS-TTS Model Loader | `MossTTSModelLoader` | 載入 Local 1.7B／VoiceGenerator |
| Load Audio | `LoadAudio` | 參考音（需先上傳到 ComfyUI input） |
| MOSS-TTS Generate | `MossTTSGenerate` | 無參考 TTS 或 Voice Clone |
| MOSS-TTS Voice Design | `MossTTSVoiceDesign` | 文字描述音色（搭 VoiceGenerator） |
| Save Audio | `SaveAudio` | 存 FLAC |

`CloudRipple/MOSS-TTS-ComfyUI` 是替代品（Local 是 4B/48 kHz），本管線的 workflow 是為
richservo 的節點寫的；換節點包要改 `workflows/moss_tts_*.json` 與 `voice_workflow.py`。

### 4.2 模型

| 用途 | `model_variant` | `engine` | VRAM（bf16） |
|---|---|---|---|
| 克隆／一般 TTS | `MOSS-TTS (Local 1.7B)` | `moss-tts-local-1.7b` | 約 5 GB |
| Voice Design | `MOSS-VoiceGenerator` | `moss-voicegenerator-1.7b` | 約 5 GB＋codec |
| 長文本（選用） | `MOSS-TTS (Delay 8B)` | `moss-tts-delay-8b` | 約 18 GB，16 GB 卡不建議 |

- 預設一律 Local 1.7B。`MOSS-VoiceGenerator` 只有 `voice_design_prompt`／`design_then_clone`
  的角色會用到；第一次使用時 ComfyUI 會自動下載到 `models/moss-tts/`。
- 輸出取樣率 24 kHz；規格要求 ≥24 kHz，轉檔後保持 24 kHz。
- 參考音 3–10 秒，單一說話者、無背景噪音；超過 15 秒容易退化。

### 4.3 workflow 模板

`workflows/moss_tts_clone_api.json`（ComfyUI API 格式）：

```
MossTTSModelLoader → MossTTSGenerate ← LoadAudio
                          ↓
                      SaveAudio (flac)
```

`workflows/moss_tts_design_api.json`：

```
MossTTSModelLoader (MOSS-VoiceGenerator) → MossTTSVoiceDesign → SaveAudio (flac)
```

`voice_workflow.fill_clone()`／`fill_design()` 只改參數，不改節點鏈。模板缺少必要節點或同類節點
重複時丟 `ValueError`。

參考音上傳：`VendorTtsBackend` 用 ComfyUI 的 `POST /upload/image`（欄位名 `image`、`type=input`、
`overwrite=true`）把參考音放進 ComfyUI 的 input 資料夾，再讓 `LoadAudio` 讀。檔名用
`<book>_<char_id>_<sha8>.<ext>`，避免不同角色互相覆蓋。

### 4.4 節點相容性補丁（2026-11-03 實測必要）

本機環境：ComfyUI 0.41.0、Python 3.12.3、torch 2.9.1+cu130、transformers 5.12.1、flash-attn 2.8.3、
RTX 5070 Ti 16 GB。`richservo/comfyui-moss-tts` 原始碼是針對較舊的 transformers 寫的，直接跑會依序
遇到以下四個錯誤；安裝後要對節點（`I:\ComfyUI\custom_nodes\comfyui-moss-tts`）打這四個補丁。
補丁內容如下，節點原始碼不進 repo（重裝節點後要重新套用）：

| # | 症狀 | 補丁 |
|---|---|---|
| 1 | `MossTTSDelayModel does not support Flash Attention 2 yet` | `utils/backend.py` 的 `resolve_attn_implementation()` 在 CUDA 固定回 `"sdpa"`（MOSS 不支援 flash-attn 2）。 |
| 2 | `'MossTTSDelayConfig' object has no attribute 'num_hidden_layers'` | `nodes/model_loader.py` 載入後把 `model.config.language_config.num_hidden_layers` 複製到 `model.config.num_hidden_layers`（transformers 5 的 `DynamicCache` 會讀它）。 |
| 3 | `'MossTTSDelayModel' object has no attribute '_get_initial_cache_position'` | 在 `model_loader.py` 給模型掛一個回傳 `model_kwargs` 的相容方法；MOSS 的 `_sample()` 自己算 cache position。 |
| 4 | `create_causal_mask() got an unexpected keyword argument 'input_embeds'` | 在 `model_loader.py` 包一層 `create_causal_mask`，把 `input_embeds`→`inputs_embeds`、忽略 `cache_position`（transformers 5 改了簽名）。 |

補丁只影響 MOSS-TTS 節點，不動 ComfyUI 本體或 transformers。重開 ComfyUI 後生效。核心程式碼：

```python
# utils/backend.py
def resolve_attn_implementation(device, dtype) -> str:
    if str(device).startswith("cuda"):
        return "sdpa"
    return "eager"
```

```python
# nodes/model_loader.py，在 model.eval() 之後
if not hasattr(model.config, "num_hidden_layers"):
    language = getattr(model.config, "language_config", None)
    layers = getattr(language, "num_hidden_layers", None)
    if isinstance(layers, int):
        model.config.num_hidden_layers = layers

if not hasattr(model, "_get_initial_cache_position"):
    def _get_initial_cache_position(cur_len, device, model_kwargs):
        return model_kwargs
    model._get_initial_cache_position = _get_initial_cache_position

module = sys.modules.get(type(model).__module__)
if module is not None and hasattr(module, "create_causal_mask") and not getattr(module, "_moss_tts_compat_mask", False):
    real_mask = module.create_causal_mask
    def _compat_create_causal_mask(*, config, input_embeds=None, inputs_embeds=None, attention_mask=None,
                                   past_key_values=None, position_ids=None, cache_position=None, **kwargs):
        return real_mask(config=config, inputs_embeds=inputs_embeds if inputs_embeds is not None else input_embeds,
                         attention_mask=attention_mask, past_key_values=past_key_values, position_ids=position_ids)
    module.create_causal_mask = _compat_create_causal_mask
    module._moss_tts_compat_mask = True
```

### 4.5 生成速度與 `max_new_tokens`

- MOSS Local 1.7B 的節點預設 `max_new_tokens=4096`；若模型沒吐出 EOS，會一路生成到上限
  （實測 13 字跑 6 分鐘還沒停）。`voice_workflow.estimate_max_tokens()` 依文字長度估
  `3.5 token／字＋40`，下限 64、上限 4096；`fill_clone`／`fill_design` 會自動套用。
- Voice Design 的參考音文字預設 `這是一段固定角色音色的參考錄音。`（約 4 秒），不要用太長的句子。
- 實測（RTX 5070 Ti）：Voice Design 約 4 秒參考音可跑完；Local 1.7B 每句 5–10 字約 1–2 分鐘，
  長句會更久。這是目前單卡可接受的迭代速度，但**不要一次跑整本書**；先挑章節與角色。

## 5. 批次與去重

- **按章批次**：`generate()` 依 `chapters` 逐章處理；一個 job 一次跑完指定章節。
- **去重**：VoiceMap 已有條目，且 `text_hash`、`config_hash`、`seed` 都相同、`assets/voice/...`
  檔案存在 → 跳過（`skipped`）。
- **`only`**：只處理指定 line_id（除錯用）。
- **`regenerate`**：忽略去重，重寫。
- **失敗隔離**：單句失敗記入 `failed[line_id]`，繼續下一句；任務結尾在 `summary.failed` 列出。
- **停止**：`should_stop()` 或後端丟 `JobStopped` 時，已完成的不回滾，任務記 `stopped`。

## 6. FastAPI

### 6.1 `POST /api/books/{book_id}/tts/generate`

```json
{
  "chapters": [1, 2],
  "only": ["ch001_sc02_l003"],
  "regenerate": false,
  "design_only": false
}
```

全部欄位可省略。回傳 `Job.public()`（kind = `tts`，`items` 是章節清單）。任務背景執行；
`GET /api/jobs/{id}` 看進度。會先驗證 `cast_voice.json`，有錯回 400，不建立任務。

### 6.2 任務卡相容端點

`POST /tts/generate`，body 多一個 `book_id`：

```json
{"book_id": "sample_book", "chapters": [1, 2]}
```

這是任務卡指定的路徑；內部與 6.1 共用同一個處理函式。

### 6.3 其他

| 方法 | 路徑 | 用途 |
|---|---|---|

## 7. Ren'Py 匯出

- 有新條目且 `game/audio/voice/...` 檔案存在時，在對白前插入：

```renpy
voice "audio/voice/ch001/ellie_reed_ch001_sc02_l003.ogg"
c_ellie_reed "你終於來了。"
```

- 不設 `config.voice_filename_format`（顯式路徑比較好除錯；之後要縮短再說）。
- `vn_export.json` 新增 `voices`：

```json
"voices": [
  {"line_id": "ch001_sc02_l003", "speaker": "ellie_reed", "file": "audio/voice/ch001/ellie_reed_ch001_sc02_l003.ogg", "present": true}
]
```

- 沒有 VoiceMap 或該句沒有音檔 → 不寫 `voice`，其他輸出完全不變。
- 匯出時只複製 VoiceMap 引用且存在的檔案；孤兒音檔不進遊戲。

   **PASS**：10 個 OGG（Vorbis 24 kHz mono、1.94–5.30 秒）、VoiceMap schema、10 個 Ren'Py `voice`。

4. 重新匯出後 Ren'Py Lint 零錯誤、遊戲中可聽到語音（尚未對 sample_book 實跑）。

## 9. 快速開始

```powershell
# 1) 節點（一次）
git clone https://github.com/richservo/comfyui-moss-tts I:\ComfyUI\custom_nodes\comfyui-moss-tts
#    套用第 4.4 節四個補丁，重開 ComfyUI

# 2) 聲線設定：把範例複製到作品資料夾，改成這本書的角色
New-Item -ItemType Directory -Force works\sample_book\voice | Out-Null
Copy-Item config\cast_voice.example.json works\sample_book\voice\cast_voice.json
#    編輯 characters：voice_design_prompt 用中文描述音色；種子固定
#    或直接用 sherpa：Copy-Item config\cast_voice.sherpa.example.json works\sample_book\voice\cast_voice.json

# 3) 先只產生設計參考音（可選，確認音色）
python -m t2vn.voice_gen --book sample_book --chapters 1 --design-only

# 4) 逐句生成（先限制一章；--only 可單句重試）
python -m t2vn.voice_gen --book sample_book --chapters 1

# 5) 重新匯出 Ren'Py；有 VoiceMap 就會自動加 voice 語句
python -m t2vn.export_renpy --book sample_book --chapters 1-5 --project <Ren'Py 專案資料夾>
```

《示範》目前用 sherpa-onnx：`cast_voice.json` 已設 `speaker_id` 20／100，模型已下載，
不需要 ComfyUI；直接跑第 4 步 `python -m t2vn.voice_gen --book sample_book --chapters 1` 即可。

也可以走 API：`POST /api/books/sample_book/tts/generate`（背景任務），或任務卡相容的
`POST /tts/generate`（body 加 `book_id`）。

## 10. sherpa-onnx（固定聲線，目前《示範》預設）

MOSS 的 Voice Design 對短句會漂、Clone 有雜音，2026-11-03 改以 sherpa-onnx 作為《示範》的預設：

- 套件：`pip install -r requirements-tts.txt`（或 `pip install sherpa-onnx`），裝在專案 venv。
  用 CLI 時請用 `.\venv\Scripts\python.exe -m t2vn.voice_gen ...`（系統 Python 沒有 sherpa）。
- 模型：`models/sherpa/vits-zh-hf-fanchen-C/`（187 speakers、16 kHz、約 116 MB；不進 git）。
  - 下載：`https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-zh-hf-fanchen-C.tar.bz2`
  - 解壓後資料夾要有 `vits-zh-hf-fanchen-C.onnx`、`lexicon.txt`、`tokens.txt` 與 `.fst`。
- 設定：`cast_voice.json` 的 `engine: sherpa-onnx`、角色 `source: speaker_id`、`speaker_id`；可選 `speed`。
- 目前 speaker：`ellie_reed = 2`、`lao_zhang = 100`（使用者選定；目前模型 `vits-zh-hf-theresa`）。
- 試聽與 spike：`models/sherpa/samples/index.html`；實際接入 smoke：`tools/sherpa_voice_smoke.py`。
- 特性：同一個 speaker id 音色固定、CPU 即可、每句約 0.5–5 秒；不需要 ComfyUI。
- 限制：16 kHz 音質偏窄；`fanchen-C` 的模型授權要再確認；若音質不夠，換 `kokoro-multi-lang-v1_1`
  （24 kHz、103 speakers）或 `vits-zh-hf-theresa`（22 kHz，但聲線來自遊戲角色，商用授權要確認）。

## 11. 已知限制

- scene graph 改動（在中間插入/刪除台詞）會讓後面的 line_id 位移；目前不做「以文字內容為錨」的
  id 穩定化。
- 沒有自動判斷情緒→語氣；MOSS 的 `voice_design_prompt` 是語氣控制，sherpa 目前只有固定 speaker 與語速。
- MOSS 的 Voice Design 短句會漂、Clone 有雜音（2026-11-03 實測）；目前已改用 sherpa-onnx，MOSS 路徑保留給有真人參考音時。
- 16 GB 顯卡跑不下 MOSS Delay 8B；`engine` 可選但不在預設路徑。
- ComfyUI 的模型下載與節點安裝不在本模組內（見第 4 節）；首次使用要等模型下載。
- 有語音頁（`ui/page_voice.js`：進度、逐句試聽、聲線選單、章節範圍、範例語音），但還沒有 Playwright／真實瀏覽器驗收。
- sherpa-onnx 的 C++ 字元詞典原本會把 `Ignore OOV '…'` 印到 stderr；`sherpa_tts` 生成時會暫時接管 fd 2，預設不顯示 OOV 洗版。要除錯時設 `T2VN_SHERPA_OOV=1`，只會印一行摘要。
