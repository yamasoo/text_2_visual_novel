# vn-review-external：審查外包模組

目的：外包程式要達到和 Claude 自己寫的一樣的標準才能合併。驗收以**任務卡＋測試**為準，不以「看起來可以」為準。

## 開始前


## 檢查順序（任一項不過就停在那裡，記錄後進入判定）

### 1. 範圍

- 只動了任務卡允許的檔案？用 `git status`／`git diff --stat` 確認。
- 如果檔案是使用者從 DeepSeek harness 貼回來的，先確認內容完整（沒有被截斷、沒有混入對話文字或 Markdown 圍欄）。
- 沒有改測試檔來讓測試通過？比對 `tests/<module>/` 與任務卡貼的版本。

### 2. 測試

- 執行任務卡的驗收指令（通常是 `pytest tests/<module>/ -v`）。
- 全部通過才往下。

### 3. 專案規則

`tools/lint_rules.py` 完成前，手動檢查：

- **非 ASCII key／識別字**：搜尋 dict key、函式名、變數名、JSON 欄位是否有中文。中文只能在字串值裡。
- **寫死路徑**：搜尋 `C:\\`、`E:\\`、`/Users/`、`/home/`。
- **寫入書目錄**：任何 `open(..., "w")`、`write_text`、`shutil.move/copy`、`os.remove` 的目標都必須來自輸出參數。
- **編碼**：所有 `open()` 有 `encoding="utf-8"`；CLI 有 UTF-8 輸出設定。
- **網路**：沒有 `urllib`、`requests`、`httpx`、`socket`（除非任務卡允許）。
- **依賴**：沒有任務卡未列的第三方套件。

`tools/lint_rules.py` 完成後，改為執行它，結果必須 0 違規。

### 4. 讀程式

- 邏輯符合任務卡描述，不只是剛好通過測試（例如針對 fixture 寫死的分支）。
- 錯誤情況有明確報錯訊息，不是默默略過。
- 沒有多餘功能（任務卡沒要求的不要加）。

## 判定

| 結果 | 條件 | 動作 |
|---|---|---|
| **通過** | 1–4 全過 | 合併；任務卡 `status: done` |
| **退回** | 有問題且能用文字說清楚怎麼改 | 寫編號修正清單（每條：檔案、行號、問題、要改成什麼），清單要能單獨貼到 DeepSeek harness 看懂；`status: rejected`，`rounds` 加 1 |
| **接手** | 已退回 2 次，或問題出在任務卡本身不清楚 | 由 Claude 修改完成；在任務卡記錄原因（卡片不清楚的話，順便修卡片範本） |

## 記錄

在任務卡底部「審查紀錄」補一行：日期、模型、第幾輪、結果、主要問題。
