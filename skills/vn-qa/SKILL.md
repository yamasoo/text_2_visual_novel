# vn-qa：獨立驗收

目的：用一個**沒看過開發過程**的對話驗收成品，避免自己審自己。兩種身分，先判斷自己是哪一個。

## 身分 A：開發端（準備驗收）

1. 確認成品齊全：工作台「輸出」頁已匯出、跑過自動驗收（五項通過）、打包 Windows 版且沒有「不該出貨的檔案」警告。
2. 產生驗收包：`python tools/make_qa_pack.py --book <書id> --out reports/qa_pack_<n>`（資料夾要是新的）。
3. 照 `docs/qa/如何開驗收對話.md` 指引使用者開新的 Opus 對話；**不要**把 `HANDOFF.md`、`decisions.md`、任務卡、開發對話的內容給驗收者。
4. 收到報告後：分類（阻擋／重要／次要／建議）、修、重新打包、**重新產生驗收包、開新對話再驗**。

## 身分 B：驗收者（工作資料夾裡有 `PACK.md`）

1. 讀順序：`PACK.md` → `docs/qa/交接說明.md` → `docs/qa/驗收清單.md` → `CLAUDE.md` → `docs/05_資料格式規格.md`。
2. 規則：**只驗收不修改**；每個結論附證據（檔案:行、章節:段落、截圖名稱）；沒驗到寫「未驗證」；原文為準；看不到的開發意圖記成「需要作者確認」。
3. 先做不需操作的區（B 複核報告與截圖、D 內容忠實度抽樣、E 資料與腳本契約），再一次請使用者做 3–5 項試玩／換機步驟（C、F）。
4. D 區抽樣用程式輔助：用 `source_para` 把 `scenes/*.json` 的每行文字對回 `source/*.json` 原文逐字比；統計每章覆蓋率；列出說話者不在 `cast.json` 的行。可以寫小腳本放在自己的暫存區，**不要寫進驗收包資料夾**。
5. 輸出 `驗收報告_<日期>.md`，格式依清單 H 區；判定規則依 G 區。
